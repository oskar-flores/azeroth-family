# AutoBalance + Transmog, Pinned Versions, Spanish Proper Nouns — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `mod-autobalance` and `mod-transmog` to the realm, replace `latest` image tags with reproducible pinned versions, and make LLM bot chat use Spanish WoW proper nouns.

**Architecture:** Three changes sharing one seam — the build machine. Modules are compiled into the worldserver via `build-and-push.sh`; their settings ride the existing `family-settings.ini` → `ini2env.py` → `family.env` pipeline. Version pinning converts floating branch refs into commit SHAs and derives the image tag from them, while continuing to publish `latest` so the running Dokploy stack is unaffected. Spanish proper nouns are a string replacement applied inside the bridge image, because the module exposes no config, data, plugin or REST surface for it.

**Tech Stack:** Bash, Docker/BuildKit (buildx), Python 3 (stdlib only), AzerothCore C++ modules, MySQL 8.4, Dokploy Compose.

**Spec:** `docs/superpowers/specs/2026-08-03-modules-pinning-spanish-nouns-design.md`

## Global Constraints

- **Never hand-write an `AC_*` variable name.** Generate every one with `python3 scripts/ini2env.py --key <Key>`. A wrong name is silently ignored — no error, the setting just never applies.
- **Edit `family-settings.ini`, never `family.env`.** Regenerate and commit both. The drift check `python3 scripts/ini2env.py family-settings.ini | diff - family.env` must produce no output.
- **Config keys must be spelled exactly as in the module's own `.conf.dist`.** Verify against the cloned source, not a wiki.
- **`family-settings.ini` is flat INI-style — no `[section]` headers.** A stray section header is silently dropped from the converted output.
- **Root files stay at the repo root.** `docker-compose.yml`, `family.env`, `llm-chatter-settings.conf`, `.env.example`, `family-settings.ini` and `build-and-push.sh` must sit beside each other; three separate consumers resolve paths relative to them.
- **Do not stage module SQL into `data/sql/custom/`.** `dbimport` already applies module SQL from `modules/<mod>/data/sql/`. A copy in both places aborts the entire import on a duplicate filename.
- **Never put a secret in `llm-chatter-settings.conf`** — it is committed to a public repo.
- **`SOAP.IP = 0.0.0.0` and `BIND_ADDR` stay as they are.** Neither is in scope.
- **Bash 3.2 compatibility.** The macOS system bash is 3.2; expanding an empty array under `set -u` is an error there, so array expansions stay guarded by a length check.
- Pinned refs, verbatim: core `190184a`, mod-playerbots `ba46fcd`, mod-llm-chatter `97274f8`, mod-autobalance `73d4ad3`, mod-transmog `0d85cbc`. Client data `17.0.0-dev`.
- Transmog NPC entry is `190010`.

- [ ] **Step 3: Replace `clone_or_update` with `fetch_pinned`**

Replace lines 96-110 entirely:

```bash
# A pin is a commit SHA, and `git clone --branch` does not accept one. So this
# is init + fetch + checkout instead of clone. GitHub serves any reachable SHA
# to a --depth 1 fetch, so it costs the same as the old shallow clone.
#
# `clean -fd` deliberately has no -x: gitignored files must survive, because the
# stale data/sql/custom check further down is what catches them, and it needs
# them to still be there to report.
fetch_pinned() {
  local dir="$1" url="$2" ref="$3"
  local name; name=$(basename "$dir")

  if [[ ! -d "$dir/.git" ]]; then
    log "Initialising $name"
    mkdir -p "$dir"
    git -C "$dir" init -q
    git -C "$dir" remote add origin "$url"
  fi

  # Prefix match: ref is usually a short SHA and HEAD is always full. A ref
  # given as a tag name never matches, so it re-fetches every run -- correct,
  # just not free.
  local head
  head=$(git -C "$dir" rev-parse HEAD 2>/dev/null || echo "none")
  if [[ "$head" == "$ref"* ]]; then
    echo "    $name already at $ref"
    return
  fi

  log "Fetching $name @ $ref"
  git -C "$dir" fetch --depth 1 origin "$ref"
  git -C "$dir" checkout -q --detach FETCH_HEAD
  git -C "$dir" clean -qfd
}
```

- [ ] **Step 4: Add the `--update` reporter**

Add immediately after `fetch_pinned`:

```bash
# --update no longer moves anything. It reports what the pins WOULD become, so
# a version bump is a commit you can see in a diff rather than a side effect of
# having run the build on a Tuesday.
report_updates() {
  local name url branch pinned head stale=0
  log "Pinned refs vs upstream heads"

  local extra=""
  if (( ${#EXTRA_MODULES[@]} )); then
    extra=$(printf '%s\n' "${EXTRA_MODULES[@]}")
  fi

  while IFS='|' read -r name url branch pinned; do
    [[ -n "$name" ]] || continue
    head=$(git ls-remote "$url" "refs/heads/$branch" | cut -f1)
    [[ -n "$head" ]] || die "could not read $branch from $url"
    if [[ "$head" == "$pinned"* ]]; then
      printf '    %-18s %-9s up to date\n' "$name" "$pinned"
    else
      printf '    %-18s %-9s -> %s\n' "$name" "$pinned" "${head:0:7}"
      stale=1
    fi
  done <<EOF
azerothcore-wotlk|$CORE_REPO|$CORE_BRANCH|$CORE_REF
mod-playerbots|$MODULE_REPO|$MODULE_BRANCH|$MODULE_REF
$extra
EOF

  if (( stale )); then
    cat <<'MSG'

Nothing was changed. To take these, edit the *_REF values at the top of this
script, commit them, and rebuild. Core and mod-playerbots move TOGETHER --
mixing versions gives compile errors or runtime crashes.
MSG
  else
    echo "    all pins current"
  fi
  exit 0
}
```

publish() {

    local alias="${image%:*}:latest"

  return 0
